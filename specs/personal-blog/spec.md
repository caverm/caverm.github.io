# 한국어 개인 블로그 기능 명세

상태: 현재 기능 계약. 2026-10-23 작성.

## 목적과 범위

`saicaca/fuwari` 원본 테마의 레이아웃, 색상, 타이포그래피, 카드와 기존 독서 기능을 보존한 한국어 개인 보안·CTF·컴퓨터공학·프로젝트 블로그를 만든다. 페이지 이동의 사라짐·등장·슬라이드·순차 표시 연출은 제거하고 메뉴, 카테고리 펼침, 호버, 복사 성공, 테마 같은 조작 피드백은 유지한다. 블로그 소스와 운영 문서는 이 프로젝트에 둔다. 패키지 설치, 개발 서버, 검사, 브라우저 테스트, 빌드는 모두 Docker Linux 컨테이너에서 수행한다. 호스트의 Node.js·pnpm·Python 설치와 실행을 요구하지 않는다.

범위에는 홈페이지 페이지네이션, 작성자 프로필과 소개, 다중 태그, 검색, 글 목차, 코드 강조와 복사, 밝은/어두운 테마, 모바일 레이아웃, SEO 메타데이터, RSS, sitemap, 계층형 카테고리와 GitHub Pages용 정적 산출물이 포함된다. 사용자 실명·연락처·외부 계정은 확정되지 않았으므로 편집 위치가 명확한 한국어 자리표시자를 사용한다.

후속 Pages CMS 편집 설정·날짜 호환·명시적 게시 action·개발 도구 숨김의 현재 계약은 `specs/pages-cms/spec.md`에서 관리한다. 원래 블로그 구현 완료 이력은 유지한다. CMS도 기존 공개/초안 경계와 단일 분류 기준을 따른다.

커밋, 원격 푸시, PR 생성, 서버 설정 변경, 실제 Pages 배포는 이번 범위에 포함하지 않는다. 서버 인증·DB·댓글 서비스·분석 서비스도 추가하지 않는다. 원본 라이선스와 필요한 출처 표시는 보존한다.

## 입력과 출력

- 사이트 설정: 사이트 제목·설명·언어, 작성자, 프로필, 공개 사이트 URL, Pages base 경로.
- 카테고리: 단일 기준 데이터 파일에 `id`, 표시 이름, 선택적인 `parentId`, 정렬값을 기록한다. ID는 표시 이름과 분리하여 안정적으로 유지한다.
- 글: 제목, 설명, 발행일, 선택적인 수정일·대표 이미지, `draft`, 카테고리 ID 하나, 태그 여러 개, Markdown 본문을 입력한다.
- 출력: 공개 글 정적 페이지, 페이지네이션, 카테고리·태그·아카이브, 검색 색인, RSS, sitemap, 필요한 에셋이다. 이미지 없는 글과 긴 제목·긴 코드도 읽을 수 있어야 한다.
- 예시 콘텐츠는 합성 자료임을 명시한다. 긴 코드, 로컬 이미지, 여러 단계의 카테고리, 서로 다른 부모 아래의 동명 카테고리, 다중 태그, 초안을 포함한다.

## 동작 계약과 인수 조건

| ID | 요구 동작 | 관찰 가능한 인수 조건 |
| --- | --- | --- |
| BLOG-01 | 원본 Fuwari 재사용 | 원본 소스의 출처와 커밋을 기록하며 라이선스를 유지한다. 주요 레이아웃과 테마 기능은 데스크톱·모바일에서 원본 구조를 기반으로 동작한다. |
| BLOG-02 | 한국어 기본값 | 기본 언어와 사용자에게 보이는 기본 내비게이션·설명이 한국어다. 이름·프로필·도메인 등 미확정 정보는 편집 가능한 자리표시자로 문서화한다. |
| CAT-01 | 임의 깊이 단일 트리 | 카테고리 정의는 한 파일뿐이다. 부모 참조로 표현하며 코드에 최대 깊이를 고정하지 않는다. 5단계 이상 합성 트리도 렌더링된다. |
| CAT-02 | 참조 무결성 | 중복 ID, 없는 부모, 자기 참조, 다중 노드 순환, 없는 글 카테고리 참조는 유용한 오류 코드/관련 ID와 함께 필수 검사 또는 빌드를 실패시킨다. 초안의 참조도 검증한다. |
| CAT-03 | 글 분류 | 한 글에 카테고리 ID는 정확히 하나, 태그는 여러 개를 지정할 수 있다. 동일 태그의 중복 입력은 중복 결과를 만들지 않는다. |
| CAT-04 | 하위 글 집계 | 부모 카테고리 페이지는 모든 자손의 공개 글을 포함한다. 표시 개수는 해당 결과의 고유 글 수와 일치하며 초안을 포함하지 않는다. |
| CAT-05 | 안정적인 주소 | 서로 다른 부모 아래 같은 이름의 카테고리가 각각 다른 주소와 글 목록을 가진다. 이름의 공백·한글·URL 특수문자는 경로 충돌이나 외부 이동을 만들지 않는다. |
| CAT-06 | 내비게이션 | 각 자식 목록은 버튼으로 접고 펼친다. 버튼에 `aria-expanded`와 연결 대상이 있으며 Enter/Space와 터치로 작동한다. 링크는 해당 카테고리로 이동한다. 현재 카테고리의 조상은 열리고 현재 항목이 구별된다. |
| CAT-07 | 탐색 맥락 | 카테고리와 글에 상위 경로 breadcrumb를 표시한다. breadcrumb의 각 조상 링크가 올바른 페이지로 이동하고 현재 위치를 전달한다. |
| PUB-01 | 초안 완전 제외 | `draft: true` 글은 직접 페이지, 홈페이지, 페이지네이션, 카테고리, 태그, 아카이브, 관련/이전/다음 글, 검색 색인, RSS, sitemap에서 제외된다. 직접 경로 요청도 글을 제공하지 않는다. |
| READ-01 | 기본 독서 기능 | 홈페이지 페이지 이동, 소개 페이지, 태그 필터와 검색이 작동한다. 글 목차의 링크가 해당 heading으로 이동하고 코드 복사가 성공 피드백을 제공한다. |
| READ-02 | 반응형·테마 | 모바일 좁은 화면에서 본문과 카테고리 내비게이션을 사용할 수 있다. 긴 코드는 코드 영역 안에서 스크롤하며 페이지 전체 너비를 늘리지 않는다. 밝은/어두운 테마와 모바일 메뉴를 조작할 수 있다. |
| READ-03 | 계속 보이는 페이지 이동 | 페이지·카테고리·글·페이지번호 링크를 클릭하면 응답 대기 중 기존 본문과 사이드바가 계속 보이고 교체한 내용은 첫 프레임부터 보인다. 본문 자체의 CSS fade/slide, 등장 애니메이션, 순차 표시 지연은 없다. URL·뒤로가기의 스크롤 복원·키보드 포커스·카테고리 선택·목차 링크와 조작 피드백은 유지한다. 위로 이동하는 viewport 스크롤은 READ-04를 따른다. |
| READ-04 | 아래쪽 링크의 부드러운 상향 이동 | 스크롤된 화면에서 태그·카테고리를 포함한 일반 내부 페이지 링크를 누르면 목적지 응답을 준비한 뒤 기존 화면이 위로 부드럽게 스크롤하고 상단에서 내용을 교체한다. 긴 현재 페이지→짧은 목적지에서도 클릭 위치와0 사이의 중간 y 프레임이 관찰된다. 이미 상단이거나 모션 줄이기 설정이면 즉시 이동한다. 뒤로가기/앞으로가기의 캐시 좌표 복원과 목차 hash 방문은 별도 상향 애니메이션 없이 처리하고, 상향 스크롤 중 처리되는 후속 링크와 history 입력은 마지막 하나를 보류했다가 현재 방문 종료 후 Swup에 넘긴다. 연속 링크 클릭이나 스크롤 중 history 이동도 멈춤 없이 마지막 처리 대상 탐색을 완료한다. 새탭·수정키와 core가 무시하는 동일 목적지 중복클릭은 기존 동작을 따른다. |
| SEO-01 | 사이트 경로 | 도메인 루트 base `/`와 프로젝트 base `/blog/` 양쪽 빌드에서 내부 링크·이미지·CSS/JS·검색 요청·피드·사이트맵·canonical 주소가 올바르다. base가 중복되거나 빠진 주소가 없어야 한다. |
| ENV-01 | Docker 전용 실행 | 문서의 동일 Compose 명령으로 초기 설치·개발·검사·테스트·빌드가 가능하다. 앱은 비루트 사용자로 실행하고 소스를 bind mount하며 node_modules·캐시는 named volume에 둔다. 호스트에는 의존성 디렉터리를 생성하지 않는다. |
| ENV-02 | 개발 공개 범위 | 개발 서버의 호스트 포트는 loopback에만 바인딩한다. 호스트에서 페이지 접근이 가능하며 외부 인터페이스에 포트를 열지 않는다. |
| ENV-03 | 재현 가능한 도구 | 호환되는 Node·pnpm과 Docker 이미지 버전을 고정하고 단일 lockfile의 frozen 설치를 사용한다. CI와 로컬이 같은 검증 진입점과 정적 산출물 경로를 사용한다. |
| QA-01 | 검증·기록 | 카테고리와 발행 필터 단위 테스트, 실제 브라우저 상호작용 검사, root/project base 정적 링크 검사가 실행된다. 실행 불가는 통과로 취급하지 않으며 tasks.md에 근거를 남긴다. |

## 정상·오류 처리

빈 카테고리는 0개임을 표시하고 내비게이션을 유지한다. 선택한 부모 카테고리에서 자손 글을 발행일 기준으로 일관되게 정렬한다. 페이지 경계를 넘어도 같은 글을 중복 표시하지 않는다. 검색 결과가 없으면 한국어 안내를 제공한다.

잘못된 분류·설정은 조용히 누락하지 않고 빌드 전에 실패시킨다. 정의 파일이나 글의 오류 위치를 식별할 수 있어야 한다. 미확정 도메인은 예시 주소임을 명확하게 표시하며, 실제 배포 전에 변경할 설정을 README에 기록한다. 테스트 로그에는 개인 정보나 비밀정보를 사용하지 않는다.

글 태그와 빌드 텍스트 입력 한도·거부 시점은 `docs/security-spec.md`의 SEC-CONTENT-02를 따른다. 한도 초과 입력을 잘라 저장하거나 검사 실패를 숨기지 않는다. 의존성 감사의 정확한 잔여 위험 분류는 실제 완화 전제와 guard가 충족될 때만 허용하며 새 위험이나 전제 변경은 실패해야 한다.

## 확인된 환경과 경계

원본 commit과 Docker Linux 환경을 확인했고 상세 설계 검토를 반영하여 구현했다. Spec Kit은 설치되어 있지 않아 설치·사용했다고 보고하지 않는다. 원시 dependency audit의 알려진 잔여 위험은 docs/security-spec.md에서 명시적으로 관리한다. 확정된 기능 계약은 이 파일이 기준이고 실행 결과는 tasks.md가 기준이다.
