## 1. 문제 개요

플랫폼 : [webhacking.kr](http://webhacking.kr)

난이도 : score 10

주제 : 필터 우회를 통한 db조회

## 2. 문제 분석

페이지의 `view-source`를 통해 확인할 수 있는 핵심 PHP 소스코드는 다음과 같다.

```php
<?php
  $db = dbconnect();
  if($_POST['id']){
    $_POST['id'] = str_replace("\\","",$_POST['id']);
    $_POST['id'] = str_replace("'","''",$_POST['id']);
    $_POST['id'] = substr($_POST['id'],0,15);
    $result = mysqli_fetch_array(mysqli_query($db,"select 1 from member where length(id)<14 and id='{$_POST['id']}"));
    if($result[0] == 1){
      solve(39);
    }
  }
?>
```

문제를 해결하기(`solve(39)` 호출) 위해서는 SQL 쿼리의 실행 결과인 `$result[0]`의 값이 `1`이 되어야 한다. 코드의 동작 흐름과 취약점 포인트를 분석해 보면 크게 세 가지 특징이 존재한다.

- **불완전한 SQL 쿼리 구문**
  - 실행되는 쿼리문을 자세히 보면 `where length(id)<14 and id='{$_POST['id']}"` 형태로 작성되어 있다.
  - `{$_POST['id']}`가 삽입되는 부분 앞에는 여는 싱글 쿼트(`'`)가 존재하지만, 뒤쪽에는 문자열을 닫아주는 싱글 쿼트(`'`)가 누락되어 있다.
  - 따라서 일반적인 문자열만 입력할 경우 닫는 싱글 쿼트가 없어 오류가 발생하며 쿼리가 정상적으로 실행되지 않는다. 즉, 사용자가 직접 입력값 끝에 싱글 쿼트(`'`)를 주입하여 쿼리 문법을 완성해야 한다.
- **필터링 순서의 논리적 허점 (**`str_replace`**와** `substr`**의 조합)**
  - 입력값 검증 로직을 보면 SQL Injection을 방어하기 위해 백슬래시(`\`)를 제거하고, 싱글 쿼트(`'`)를 두 개(`''`)로 치환(Escape)하는 `str_replace` 함수가 먼저 동작한다.
  - 하지만 그 직후에 `substr($_POST['id'], 0, 15)`를 통해 문자열을 앞에서부터 15바이트(0번째 인덱스부터 15글자)만큼만 잘라낸다.
  - 만약 입력값의 15번째 자리(인덱스 14)에 싱글 쿼트(`'`)를 배치하면, `str_replace`에 의해 15번째와 16번째 자리가 `''`로 늘어난다. 이후 `substr` 함수가 15글자까지만 자르면서 16번째 글자인 두 번째 `'`가 잘려 나가게 되고, 결과적으로 이스케이프가 풀린 **단일 싱글 쿼트(**`'`**) 하나만 남게 되어 필터링을 우회할 수 있다.**
- `length(id) < 14` **조건과 길이의 모순**
  - 단일 싱글 쿼트를 남기기 위해서는 무조건 15번째 자리에 `'`를 위치시켜야 하므로, 앞의 14자리를 무언가로 채워야 한다.
  - 그러나 쿼리의 첫 번째 조건인 `length(id) < 14`는 DB의 `member` 테이블에 저장된 실제 `id` 컬럼 값의 길이가 14바이트 미만이어야 함을 의미한다.
  - 즉, 14글자 미만의 실제 존재하는 계정(예: `admin`, `guest`, `1` 등)과 매칭시키면서 동시에 입력 문자열의 15번째 자리에 `'`를 배치해야 하는 모순을 해결해야 한다.

## 3. 플이 과정

### 3.1. MySQL의 후행 공백 무시(PAD SPACE) 특성 활용

앞선 14글자의 길이를 맞추면서 동시에 14바이트 미만의 `id` 컬럼 값과 일치시키기 위해 **MySQL의 문자열 비교 특성**을 활용할 수 있다.

- MySQL(특히 `CHAR`, `VARCHAR` 타입의 기본 Collation)은 `=` 연산자로 문자열을 비교할 때 **PAD SPACE** 규칙을 따른다.
- 이 규칙에 의해 문자열의 끝부분에 붙은 공백(Trailing Spaces)은 비교 연산 시 모두 무시된다. 즉, DB 내부에서는 `'admin'`과 `'admin '`(뒤에 공백이 붙은 문자열)을 동일한 값(`True`)으로 판정한다.
- 또한 `length(id) < 14`에서 `id`는 사용자 입력값이 아니라 **DB 테이블에 저장된 컬럼의 원본 값**을 의미하므로, 입력값 뒤에 공백을 아무리 많이 붙여도 DB에 저장된 원본 데이터의 길이가 14 미만이라면 해당 조건은 참(`True`)이 된다.

### 3.2. 페이로드(Payload) 구성 및 실행

일반적인 워게임의 DB 테이블에 기본값으로 존재하는 계정인 `admin`을 타겟으로 잡고 총 15바이트 길이의 페이로드를 구성한다.

- **타겟 ID가** `admin`**(5글자)일 경우:**
  - `admin` (5바이트) + `공백 9칸` (9바이트) + `'` (1바이트) = **총 15바이트**

```sql
select 1 from member where length(id)<14 and id='admin         '
```

- 닫는 싱글 쿼트(`'`)가 정상적으로 삽입되어 쿼리 문법 오류가 해결된다.
- MySQL의 후행 공백 무시 특성에 의해 `id='1'`(또는 `id='admin'`)과 동일하게 비교가 수행된다.
- 해당 레코드의 원본 `id` 길이는 14 미만이므로 `length(id)<14` 조건도 통과하여 `$result[0]`에 `1`이 반환되고 문제가 해결된다.
